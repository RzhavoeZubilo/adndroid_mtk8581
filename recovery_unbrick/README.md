## 🔍 История инцидента и суть проблемы

Головное устройство BMW E90 (платформа `uis8581a2h10_Automotive`, Unisoc UIS8581A, Android 10) окирпичилось в процессе обновления до OTA 6.67:
* Загрузчик заблокирован (`flash.locked=1`).
* Повреждены динамические метаданные разделов `super` (AVB Error Code 6: `INVALID_METADATA`).
* Бесконечный цикл перезагрузки в режим `Fastboot Mode` (`0123456789ABCDEF fastboot`).
* В Recovery режим `Apply update from SD card` не видит USB-флешки (контроллер жестко зафиксирован в режиме USB Device для ADB).
* Цельный заводской архив `update.zip` (1.9 ГБ) и даже крупные разделы (>500 МБ) обрывались при потоковом `adb sideload` из-за переполнения PageCache ядра в FUSE и срабатывания аппаратного сторожевого таймера (Watchdog ~60 с).

## 💡 Архитектура решения: Блочный модульный Sideload

### 1. Прорыв в цифровой подписи (Реверс-инжиниринг AOSP `verifier.cpp`)
Исправлены 2 критические ошибки подписи SignApk:
* **Флаг `-noattr`**: Убран мусор S/MIME атрибутов, ломавший структуру ASN.1 в `read_pkcs7()` (ошибка `Could not find signature DER block`).
* **Точный размер хеширования**: Исключены 2 байта поля длины комментария (`signed_len = length - comment_len - 2`), устранив ошибку `failed to verify whole-file signature`.

### 2. Блочная нарезка (Block-Range Slicing)
Все разделы были разбиты на независимые суб-пакеты размером до ~300 МБ с помощью Brotli-компрессии:
* Каждый пакет передается по USB за 10–18 секунд.
* Верификация подписи занимает всего 15–25 секунд.
* Запись в eMMC завершается с кодом `Install completed with status 0`.

## 👆 Как управлять меню Recovery (жесты)

Поскольку на лицевой панели ГУ нет физических кнопок громкости, навигация в меню Recovery осуществляется сенсорными жестами (свайпами) по экрану:

* **Свайп сверху вниз (Swipe Down)**: переместить курсор на один пункт вниз.
* **Свайп снизу вверх (Swipe Up)**: переместить курсор на один пункт вверх.
* **Свайп слева направо (Swipe Right)**: подтвердить выбор текущего пункта (Enter).

## 🧰 Описание инструментов в папке scripts/

| Скрипт | Назначение |
| :--- | :--- |
| **`sign_ota.py`** | Подписывает ZIP-архив обновления подписью AOSP Whole-file PKCS#7 (SignApk) с флагом `-noattr` и точным смещением DER. |
| **`verify_ota.py`** | Точная эмуляция AOSP `verifier.cpp` (проверка ASN.1 дерева, смещения 18 и SHA-1 хеша). |
| **`build_split_product.py`** | Нарезает `product.img` на 2 пакета по блокам (`0..180000` и `180000..357780`), каждый до 320 МБ. |
| **`build_split_system.py`** | Базовый скрипт деления `system.img`. |
| **`build_system_parts_2_and_3.py`** | Нарезает вторую половину `system.img` на ультра-легкие пакеты по 173 МБ и 295 МБ. |
| **`build_firmware_base.py`** | Собирает 2 МБ OTA-пакет с `SPL`, `uboot`, `trustos`, `sml`, `teecfg`, `dtbo`. |
| **`sideload_runner.py`** | Автоматизирует переход Fastboot -> Recovery, ожидает активации ADB Sideload на экране и передает пакет. |
| **`extract_partition_img.py`** | Извлекает сырые `.img` образы динамических разделов из `update.zip` через Brotli и rangeset. |
| **`recovery_diag.py`** | Диагностический скрипт: сбор `dmesg`, `pstore/ramoops`, точек монтирования и свойств. |
