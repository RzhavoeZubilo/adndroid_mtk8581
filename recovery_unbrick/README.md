## 🛠 Необходимое оборудование и программы

1. **Кабель**: USB-A — USB-A (папа-папа), подключенный к разъему **USB 1** магнитолы и к компьютеру.
2. **Компьютер**: Windows / macOS / Linux с установленным Python 3 и OpenSSL.
3. **Утилиты Android**: `fastboot` и `adb` (рекомендуется расположить в пути без пробелов, например `C:\platform-tools\` или `D:\pt\`).
4. **Ключи подписи**: Файлы `testkey.x509.pem`, `testkey.key` (находятся в папке [`recovery_unbrick/keys/`](file:///D:/BMW%20Dash/adndroid_mtk8581/recovery_unbrick/keys/)).

## 🚀 Быстрый старт: Восстановление за 3 шага

### Шаг 1: Проверка подключения в Fastboot
Подключите кабель к USB 1 магнитолы и ПК. В терминале выполните:
```cmd
fastboot devices
```
Вы должны увидеть строку с серийным номером:
```text
0123456789ABCDEF    fastboot
```

Если раздел ядра еще не прошит, прошейте его напрямую:
```cmd
fastboot flash boot C:\platform-tools\boot.img
```

---

### Шаг 2: Прошивка первого этапа (Vendor + Boot + Socko)

Для обхода лимита оперативной памяти рекавери подготовлен легкий пакет **`vendor_boot_ota.zip`** (всего 233 МБ):

Запустите автоматический раннер:
```cmd
python recovery_unbrick\scripts\sideload_runner.py C:\platform-tools\vendor_boot_ota.zip
```

1. Скрипт сам отправит команду `fastboot reboot recovery`.
2. Экран магнитолы перезагрузится в стандартное меню **Android Recovery**.
3. На экране магнитолы выберите **«Apply update from ADB»** (см. раздел [Жесты](#как-управлять-меню-recovery-жесты)).
4. Скрипт зафиксирует режим `sideload` и передаст пакет на устройство.
5. На экране отобразится:
   ```text
   Target: SPRD/uis8581a2h10_Automotive/...
   Patching vendor image unconditionally...
   Patching socko image unconditionally...
   Writing boot image...
   Install completed successfully!
   ```

---

### Шаг 3: Прошивка разделов Product и System

После завершения первого этапа устройство снова будет в меню Recovery.
Выберите еще раз **«Apply update from ADB»** и прошейте оставшиеся разделы:

```cmd
python recovery_unbrick\scripts\sideload_runner.py C:\platform-tools\product_ota.zip
```
Затем:
```cmd
python recovery_unbrick\scripts\sideload_runner.py C:\platform-tools\system_ota.zip
```

После завершения выберите в меню рекавери **«Reboot system now»** — магнитола успешно загрузится в штатную систему Android!

## 👆 Как управлять меню Recovery (жесты)

Поскольку на лицевой панели ГУ нет физических кнопок громкости, навигация в меню Recovery осуществляется сенсорными жестами (свайпами) по экрану:

* **Свайп сверху вниз (Swipe Down)**: переместить курсор на один пункт вниз.
* **Свайп снизу вверх (Swipe Up)**: переместить курсор на один пункт вверх.
* **Свайп слева направо (Swipe Right)**: нажать Enter / подтвердить выбор текущего пункта.

> **Пример для входа в Sideload**: сделайте свайп вниз (курсор встанет на `Apply update from ADB`), затем свайп вправо для активации.

## 🧰 Описание инструментов в папке scripts/

| Скрипт | Назначение |
| :--- | :--- |
| **`sign_ota.py`** | Подписывает любой ZIP-архив обновления полновесной цифровой подписью AOSP Whole-file PKCS#7 (SignApk). Поддерживает ключ `--verify` для проверки. |
| **`verify_ota.py`** | Точная программная эмуляция верификатора `verifier.cpp` из исходников AOSP Recovery. Проверяет корректность смещения блока подписи и контрольную сумму. |
| **`build_modular_ota.py`** | Автоматически нарезает заводской 1.9 ГБ архив `update.zip` на компактные модульные пакеты под нужные разделы и подписывает их. |
| **`sideload_runner.py`** | Интерактивный помощник: переводит ГУ из Fastboot в Recovery, дожидается выбора ADB Sideload на экране и льет прошивку с отображением процентов. |
| **`recovery_diag.py`** | Безопасный диагностический скрипт: снимает логи `dmesg`, точки монтирования, системные свойства и логи рекавери. |

## ⚠️ Почему обрывается передача через ADB Sideload

1. **Флешки не работают в Recovery**:
   Пункт меню `Apply update from SD card` рассчитан на физический слот MicroSD на плате (`/dev/block/.../mmcblk1p1`). Порт USB в ядре рекавери аппаратно заблокирован в режиме периферии (USB Device для ADB). Флешку рекавери не видит.
2. **Нестабильность FUSE / USB при Sideload**:
   При передаче файла через `adb sideload` рекавери монтирует его через виртуальную ФС FUSE и читает весь файл целиком для проверки хеша SHA-1 (`Verifying update package...`).
   В наших логах передача обрывалась в разные моменты: **на 18% (~340 МБ)** и **на 27% (~514 МБ)**, после чего магнитола жестко перезагружалась в Fastboot.
   Сам размер 1.9 ГБ допустим (из локальной памяти `/data/media/0` он проверяется без сбоев), но при потоковой передаче по USB происходят:
   * Накопление страниц FUSE в кэше ядра Linux (Page Cache);
   * Срабатывание аппаратного сторожевого таймера (Watchdog) процессора Unisoc (тайм-аут 45–60 с);
   * Либо помехи/просадка питания по кабелю USB-A — USB-A.
3. **Решения**:
   * **Этап 1 (`vendor_boot_ota.zip`, 233 МБ)**: легкий пакет проходит проверку за ~15 секунд и позволяет сразу проверить жизнеспособность sideload.
   * **Диагностика через `pstore / ramoops`**: чтение `/sys/fs/pstore/console-ramoops-0` после сбоя покажет точную причину ядра перед ребутом (OOM, Watchdog или обрыв USB).
   * **Альтернатива через Fastbootd**: встроенный в рекавери `fastbootd` (`fastboot reboot fastboot`, проверка `fastboot getvar is-userspace`) позволяет шить динамические разделы напрямую из сырых `.img` файлов без sideload и FUSE.
